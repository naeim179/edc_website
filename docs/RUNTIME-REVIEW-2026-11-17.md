# معالجة نتائج مراجعة ١٧ نوفمبر ٢٠٢٦

## بطاقة تصحيح الواجب — أُصلحت

كان اسم الطالب في المظهر الليلي فاتحًا فوق خلفية فاتحة ثابتة، بنسبة تباين 1.09:1. أصبحت خلفيات البطاقة ونصوصها وحدودها وأزرارها تستخدم متغيرات الهوية نفسها. لا تغيير في منطق التقييم أو إعادة التسليم أو صلاحيات المدرس.

التحقق:

- ١٩٢ اختبار تطبيق ناجح، منها اختباران لمنع تكرار الخلل والتأكد من تباين النصوص والأزرار في المظاهر الثلاثة.
- معاينة المكوّن الحقيقي وملفات التنسيق المبنية في المتصفح: ٤٨ حالة، تجمع العربية والإنجليزية، والعرضين 390 و1440، والمظاهر الثلاثة، وحالات submitted وlate وgraded وreturned. لم يرصد axe مخالفات ضمن WCAG 2 A/AA و2.1 AA. استدعاءات التقييم في هذه المعاينة معزولة عن قاعدة البيانات.
- بناء Next.js وبناء Vinext وفحص الأنواع ناجحة؛ فحص التنسيق بلا أخطاء مع تحذيرات الصور العشرة السابقة.

## أخطاء الاستضافة 503 — سبب مؤكد، لم تُعالج نهائيًا

أكد التتبع الحي `exceededCpu` ورسالة `Worker exceeded CPU time limit.` عند 10ms. وفي نافذة المراجعة ظهرت ٧٥ استجابة بسبب تجاوز الموارد. لا يوجد حد CPU مخصص في إعدادات العامل المنشور.

في إعادة الفحص نجحت صفحات الدخول والدورات وملف الشعار؛ سجّل التتبع أيضًا طلبين ناجحين يستهلكان 26ms و25ms. سماح المنصة المؤقت بتجاوز الحد يفسر نجاح بعض الطلبات، ولا يضمن الاستقرار. لا يُعد نجاح HTTP 200 أو إعادة النشر علاجًا لسبب المشكلة.

الخطة المجانية تسمح بـ10ms لكل طلب، بينما تستخدم المنصة عرض React من الخادم، بما فيه صفحة الدخول. لم نغيّر التخزين المؤقت لصفحات المستخدمين أو الصلاحيات لتجاوز الحد. ولا يُقترح تحويل المنصة إلى بنية مختلفة ضمن إصلاح ألوان البطاقة.

### الإجراء المقترح بعد موافقة صاحب الحساب على التكلفة

1. التحقق من خطة Workers الفعلية في لوحة Cloudflare، ثم تفعيل Workers Paid إن كانت مجانية. يبدأ الاشتراك المعلن من 5 دولارات شهريًا، وتوجد رسوم استعمال إضافية عند تجاوز الحصص؛ ليس مبلغًا شهريًا ثابتًا مضمونًا. اتصال OAuth الحالي لا يملك صلاحية قراءة الفوترة أو تغييرها.
2. بعد تأكيد الخطة، إضافة الحد التالي في المصدر `wrangler.jsonc` وإعادة البناء والنشر. هذا حد مقترح ولم يُضف إلى الإعداد المنشور:

   ```json
   "limits": { "cpu_ms": 1000 }
   ```

3. التحقق من إعداد الإصدار المنشور، ثم إعادة تجربة الدخول بالأدوار الثلاثة، والواجبات، والرسائل، والعودة من PayTabs إلى CliQ دون خصم. مراقبة `exceededCpu` وزمن المعالجة في تتبع مؤقت أثناء الاختبارات، مع تنظيف بيانات التجربة.
4. مراجعة الاستعمال والفاتورة في لوحة الحساب؛ حد المعالجة لكل طلب لا يمثل سقفًا للفاتورة الإجمالية.

لم يُفعّل اشتراك أو سجل مدفوع أو خدمة جديدة. يظل هذا البند مفتوحًا حتى التحقق بعد تعديل الخطة والحد الفعليين.
